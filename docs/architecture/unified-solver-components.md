## Inventory conclusion for reuse planning

The safest reusable building blocks are narrowly named: shared CFR/action structures where semantics match; fixed-board ranked terminal values; physical count tables with authenticated coverage; and independent numeric/exact replay frameworks. Full continuation solving belongs to the enclosing game entry point that owns the public tree, chance law, information sets, stack accounting, and requested-work admission. The docs explicitly forbid treating a count/equity utility as a continuation solver, a selected chance game as a full-deck approximation, or bounded finite-game accuracy as unrestricted NLHE quality. Do not compose adapters across those boundaries without Sol reviewing the architecture first.

The accompanying [machine-readable index and artifact hashes](unified-solver-inventory.json) covers 68 `pokerlab` modules, 237 script modules, 308 test modules, three native C files, 623 benchmark artifacts (527 under `benchmarks/results/`), and Python AST definitions with line numbers. All 623 raw benchmark-file SHA-256 values matched between the pre-report and post-report snapshots. 428 worktree byte streams match the pinned Git blob bytes directly; the remaining 195 differ only after checkout conversion, and all 623 canonical Git-clean-filter object IDs match pinned `HEAD`. The JSON records both raw and canonical identities.

No tests, training, benchmarks, or new measurements were run for this inventory. It only records source inspection at the pinned commit; validation results mentioned above are the repository's retained documentation and artifacts.
