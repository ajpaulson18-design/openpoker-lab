# Luna handoff: bounded same-decision follow-ups

Architecture decision · 2026-10-07 · one implementation slice

## Objective

Let a person ask a short follow-up about the **same selected saved decision** without losing its evidence binding. Add a small server-owned, in-memory conversation ledger and a browser turn list with “Simpler” and “Go deeper” controls. The model still selects only a validated `CoachReplyPlan`; the server renders facts and the locally authored teaching note. This slice provides follow-up continuity, not free-form model prose, streaming, automatic coaching, or a permanent chat history.

## Starting point

Start from merged [PR #33](https://github.com/ajpaulson18-design/openpoker-lab/pull/33), `7a7330797280ad05f3acec8d35cbeb5cfa66b6fe`. Its final head `17f73d0` passed 191 local tests and both GitHub workflows. Preserve the existing one-shot endpoint and strict request shape for compatibility. Keep external AI off by default and separately opted in for every question; retain its `store: false`, timeout, bounded output, separate coach admission gate, deterministic fallback, and renderer/teaching-note trust boundaries.

## Conversation contract

Add a versioned follow-up route such as `POST /api/v1/coach/turns` with `{conversation_id?, client_turn_id, target:{hand_id, decision_id, evidence_id, state_revision}, question, detail, audience}`. Keep the same per-request external-AI opt-in control. The server loads the selected decision through `_validated_decision`, rebuilds its grounding bundle, and requires every target field to match trusted saved evidence. The browser never supplies prior facts, replies, plans, or a conversation summary as authority. Unknown or expired conversation IDs, cross-hand/decision/evidence reuse, mismatched target revisions, conflicting reuse of a client turn ID, and simultaneous turns in one conversation fail with safe explicit responses.

On the first accepted turn, create an unpredictable conversation ID bound to the exact hand, decision, evidence ID, and revision. Accept at most four total turns per conversation; a fifth returns a clear `conversation_full` result and the browser can start a new conversation for the same decision. Retain only a small server-owned record of those turns: bounded question text, validated intent/target action/detail/audience, server-rendered reply identity, and local teaching template ID if present. Include prior question text in a provider call only when this request has explicit external opt-in; update the UI disclosure to say recent questions for this decision are then sent too. Facts, numeric values, source labels, and caveats are regenerated from the current trusted bundle, never reused from an earlier model output or user text. A “simpler” or “deeper” follow-up may change audience/detail; it cannot switch evidence or turn an unassessed size into an assessed one.

Use a lock only for short ledger operations. Never hold a ledger lock, `game_lock`, or SQLite transaction across a provider wait. Reserve one in-flight turn per conversation and release it on every success/failure path. Keep total conversations and turns bounded, expire idle conversations after a short fixed period (for example 30 minutes), and make the time source injectable for tests. A repeated `client_turn_id` with the same normalized payload **including its external-AI opt-in** returns its completed result without another provider call; a conflicting payload fails. Do not persist question text to SQLite, exports, logs, or hand records in this slice. A server restart may end the conversation with a clear expired status; the saved decision and one-shot study still work.

Extend the narrow plan-selector interface additively to accept a bounded, server-created prior-turn context. The OpenAI adapter may receive at most the last two prior questions and validated plan metadata plus the current allowlisted grounding bundle. Preserve the existing strict reply-plan schema; no provider-written teaching text or strategy values. If history is unavailable or a provider fails, return a local fallback with the same binding and mandatory caveats. Do not silently route to another provider. Treat user questions, including adversarial instructions, as data.

## Browser behavior

Show a compact chronological turn list under the selected decision's study cards. Keep the existing Ask form and add **Simpler** and **Go deeper** actions for the latest turn; they submit an explicit follow-up for the same decision with adjusted audience/detail and a new client turn ID. Show which turns used external AI versus local fallback. Keep the question, source label, rendered facts, local teaching note, and limitations together. Maintain a browser-side conversation ID only for its exact hand/decision/evidence binding; a new hand clears it, while reopening the same decision in this browser session may restore its turns. Offer an explicit new conversation after the four-turn limit. Before showing each completed turn, verify the full binding and current selection generation. A late turn from another selection never replaces the current panel. Keep poker controls responsive, render text safely, and avoid automatic provider calls when a hand advances or a panel opens.

## Verification and stopping rule

Test first turn, two same-decision follow-ups, simpler/deeper setting changes, a four-turn cap, expiry, duplicate client-turn retry without extra provider spend, conflicting duplicate IDs, concurrent turns, provider failure and disabled fallback, strict cross-decision/evidence/revision rejection, and no game-lock contention. Assert that provider context includes only bounded prior questions and validated metadata; numeric facts come from the freshly rebuilt bundle. Exercise stale browser replies after a new decision, new hand, and Blind Play toggle. Verify the rendered UI with a fake provider and with external AI disabled. Run focused and full tests, publish one narrow PR, and stop for Sol review before merging. Do not add SQLite conversation storage, SSE, cancellation, provider-authored prose, automatic after-action AI, or solver changes in this slice.
