# Native river range-quality protocol v1

This protocol defines one four-call, fixed-budget river accuracy study. Publish and freeze its source, case manifest, and protocol before the study. Authenticate all preflight inputs before creating the exclusive claim; then run the four calls exactly once. It makes no speed claim.

## Scope and frozen design

The case manifest is the single source of truth: two weighted literal 8x8 river ranges, two full five-card boards, CFR+, discard 0, T=10,000, and exactly four calls in order: Python materialized D=0 then native for Case A, followed by Python materialized D=0 then native for Case B. Case A reuses FRESH_CASE from the prior compiled controls and must not be described as newly held out. Case B is the paired 9h8h7h2c2d design. The reporting threshold is exact NashConv <= 1/1000. It never stops training. Policy probability parity is 1e-9; numeric metric parity is 1e-8.

D=0 is the original linear completed-sweep averaging schedule. For T=10,000, metadata must report window [1,T], 10,000 average passes, and sum of weights T(T+1)/2 = 50,005,000. Validate those fields on every returned policy; include algorithm, schema, all eight standard metrics, full strategy rows and action metadata, counts, resource admission, training-call count, and native solver/build receipt. Native receipts must identify solver/execution version and admission. Compare config, complete native build identity, and full admission with canonical JSON bytes so booleans cannot substitute for numeric fields. Do not infer or fill missing metadata.

## Calls and raw policy preservation

Invoke exactly four requested calls, once each, and no warm-up, tuning, retry, or replacement. For every successfully returned JSON-serializable payload, first write the complete raw result/policy using canonical UTF-8 JSON with sorted keys, compact separators, and one LF. Use exclusive file creation and fsync, then reload, rehash, and store policy bytes and hashes in status. Do not validate policy metadata, audit, or compare any policy until all four raw policies are saved and reloaded successfully. A missing or falsified metadata field then marks only that policy invalid with an unknown quality gate; continue auditing every other saved policy. The report must say completed-with-audit-errors when any policy is invalid and must not make an accuracy claim for that policy.

If a trainer throws, source/build identity changes, or a payload cannot be canonically serialized and saved, stop the remaining calls, atomically preserve the first failure and status, and retain all prior saved raw policies and receipts. Do not retry. A malformed but successfully serialized returned policy is retained, and the fixed four-call sequence continues; its post-batch validation marks its own replay invalid while independent audits continue for the other saved policies. Never claim accuracy for invalid policies.

## Independent replay and exact audit

Only after all four raw policies are saved, reload them from disk and independently audit each with scripts/turn_river_validation.py physical numeric rules, scripts/preflop_validation.py independent rank evaluation, and scripts/turn_rational_certificate.py exact oracle. Do not use production public-game diagnostics for the audit. Run numeric physical replay and both exact chance groupings, scan and partition, at the frozen exact limits of 100,000 work, depth 64, and 65,536 Fraction bits. Retain complete eight-metric numeric and exact rows, all action metadata, rank/tie/blocker counts, physical worlds, decisions, terminals, refund terminals, information rows, admission work, and audit provenance.

A numeric policy-replay error marks that policy replay invalid and its quality gate unknown, records the failure, and continues auditing every other already-saved policy. An exact-cap rejection is recorded explicitly as admission-rejected with target flag null; do not convert it into a miss or pass. An unexpected exact-audit failure is separately recorded as invalid/unknown. Never erase raw policies or a successful independent audit because another backend or parity failed.

After independent audits, compare each native/Python pair by maximum absolute action probability (1e-9) and each of the eight metrics (1e-8). A parity failure is retained as a parity failure and does not cancel, hide, or rewrite either independent accuracy result or target flag. Compare fully reloaded serialized policies.

For every exact-admitted policy, report exact NashConv and target_met iff NashConv <= 1/1000. Retain all target misses. No quality-based stopping is permitted. No comparative runtime, throughput, equal-cost, or speed claims are allowed; equal requested T does not make costs equal.

## Claims

The permitted conclusion is limited to the observed four policies on these two frozen finite river abstractions under this exact replay procedure. Do not generalize to arbitrary ranges/boards, full no-limit Hold'em, guaranteed convergence, or relative performance.
