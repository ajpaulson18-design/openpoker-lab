# Exact integer four-street integration: frozen result

The [explicit dyadic query core](exact-dyadic-arithmetic.md) preserves complete
four-street policies and diagnostics under the same exact-product game. Its
first fixed 14-call study completes at source
`9d8a084a08ddf24dded3a4c76b1bb60ba914df3e` (terminal 9783, exit 0). Independent
saved-only review authenticates 1,791 source files and the full externally pinned
archive before twelve numeric policy replays and six exact certificates.
All paired policies/eight metrics and exact certificates agree. Runtime gains
are mixed, and Python allocation increases. Final CI/publication is PR #260;
native exact computation and scalable strategy/history storage remain open.

The [protocol](../benchmarks/results/exact-dyadic-selected-v1/protocol.json),
[report](../benchmarks/results/exact-dyadic-selected-v1/report.json),
[complete archive](../benchmarks/results/exact-dyadic-selected-v1/study.zip),
[independent receipt](../benchmarks/results/exact-dyadic-selected-v1/receipt.json)
and [publication pins](../benchmarks/results/exact-dyadic-selected-v1/publication.json)
retain all raw streams, policies, exact misses/passes, cap failures and source
identities. Python 3.12.14/Windows runtime metadata is pinned in the protocol and
every child, without implying portability of bitwise trajectories across Python
versions. All calls use compact diagnostics and rank-cache capacity 64; request
parsing/instrumentation precede measured complete solves, and independent
certification runs outside child timing. No production pair queries or native
execution occur.

## Admission and representation controls

The original 22-world dyadic T1000 request rejects the unchanged work admission
in 0.070502 s, with zero ranking/training/pair/native calls. Faster arithmetic
does not reopen that request. Setup adds a separately admitted integer snapshot;
actual modeled kernel work and payload receipts remain under whole-request
forecasts. At original T10, both modes have the same conservative 365,774 modeled
retained-peak entries (other constructor reservations dominate). Integer actual
peak operand width is 216 bits, forecast peak 225 bits, and per-query modeled
integer-payload peak 307,120 bits. These are scoped logical counters, not measured
allocator bytes. The limb receipt covers a counted query-core/output subset;
Fraction validation/GCD preflights, setup, runtime and adapter costs remain outside.

The final full-range one-selected-board forced blind-all-in control completes in
0.565094 s: 1,326 input hands/seat, 1,070,190 compatible deals, 2,162 per-hand ranks,
zero decisions/training/pair/native calls and an empty strategy. Uniform input
witness and all eight symmetry values/BRs/gains agree within 1e-12. Its modeled
retained peak is 731,823 entries and requested combined work upper 6,788,340.
The unchanged independent certificate rejects its four-hands/seat cap before
building any physical model. It has no larger exact certificate and is not
full-range choice-bearing training or a full-deck solve.

## Independent replay and profiling

The reviewer authenticates every raw working-source SHA256 against the captured
committed tree (raw or attribute-normalized Git blobs), all manifest artifacts,
the whole archive and source before/after. Only then do independent physical
numeric rules and v3 exact mathematics import. Production solve/training,
exact-kernel and integer-plan constructors/callbacks, native helpers and subprocess
execution are forbidden throughout twelve numeric replays and six fresh exact
certificates. Numeric gaps are at most about 1.11e-16. Each compact exact replay
independently measures three physical model builds. Every compact witness is
checked against independently parsed inputs; every repeated game declaration,
report field, comparison, median and certificate binding is checked. All current
source and saved artifact bytes remain unchanged afterward. This verifier still
materializes capped physical support and does not solve scalable certification.

Separate fresh-process T10 profiles authenticate the same source and reproduce
their complete frozen policies/eight metrics. The profiler records 2,044,487
calls to `fractions.Fraction.__new__` on the reference versus 46,098 on the integer
path. This is a named-method call count, not a census of every Fraction allocation.
Both paths still perform 16,215 reference Fraction terminal-bit preflights; the
integer path additionally performs 16,215 dyadic preflights. The data identifies
redundant validation work worth considering, but does not establish its causal
effect on any benchmark result. Profiler durations carry instrumentation overhead
and are not substitute speed measurements. Raw
