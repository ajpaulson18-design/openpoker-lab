# Callback-scoped native role lease

Status: original native component execution passes in both Python modes.
The [integration contract](opponent-role-integration-contract.md)
still requires a complete native sampled walk and independent literal-history
transcript parity before whole-game admission.

The [facade](../native/virtual_opponent_role_epoch.hpp) privately owns the
existing sparse Store. History, Catalog and Prepared chance remain the shared
authorities, with eager Catalog storage, canonical denominators, implicit
uniform rows, signed unclipped regrets and the original two-epoch lifetime.
There is no second strategy database or production/default change.

Construction binds one compact joint-ticket chance owner, Catalog, History
and ordered range dimensions. `apply_world(ticket, rank, callback)` obtains
the certificate from that bound chance owner; a foreign certificate cannot be
supplied through this API. The noncopyable, nonmovable epoch exists only in
the certificate callback. Its frozen reads verify selected own holdings,
the same deck and certified visible board prefix. The exact full History
ordinal, actor and original own holding form the cache key. Numeric source
IDs never replace complete visible information identity.

The first visit obtains the existing Catalog RowId and current frozen policy;
the opposite target can reuse it in the same epoch. Each target has its own
role bit, and duplicate same-target visits refuse. Both root phases, ordered
SB then BB, must finish before sealing. Staging checks owner/generation-qualified
tokens, observed roles, legal menu, exact frozen Q52 average units or required
zeros, bounded centered regrets, and duplicate stages. Values expand exactly
from compact `2^365`/Q52 to canonical Store scales at that boundary.

Tokens retain a small unique identity object, never strategy data. This
prevents a stale token becoming valid if a later Store occupies the same
memory address. The identity allocation and cache bookkeeping are included
in the fixed component reservation; producer-held raw rows/tokens belong to
the later whole-walk reservation. Borrowed policy views remain callback-scoped.

The epoch closes and all borrowed cache views disappear before Prepared
accepts callback completion. Only then can the facade publish the pending
Store image. Failed, abandoned, reentrant or internally caught invalid
operations poison the facade; its private Store cannot be committed through
another public entry. A callback error after complete staging also prevents
publication. Committed-image export remains guarded and read-only.

## Resource and validation boundary

Scalar admission combines the unchanged Store forecast, the extra History
checks, bounded role/cache/staging work, directory/identity storage and exact
conversion scratch. Its limits are reduce-only under the original Store
75-million work, two-million entries and one-Gibit payload caps. It reserves
at most 204 cached rows, 816 action slots and 204 role encounters per world,
with cumulative T2 read and staging bounds. These are component limits, not
a complete native solver request forecast or measured memory.

The native control program reserves its entire independent validation batch
before template/range/History preparation: one template, two History owners,
one Catalog, up to64 small facade/chance owners, input/output and scratch,
inside the original global caps. No limit is increased or lifetime counter
reset to claim admission. Separate fresh owners are independent synthetic
guard scenarios, not pieces of one longer learning run.

Executed checks cover 44 real refusals, three compile-time scope
checks, two evolving root updates, average-only and regret-only BB visits,
and distinct full histories sharing one numeric source. The latter must
produce three unique cached rows. A deliberate destruction/reconstruction at
the same Store address tests token identity. Each rejected update preserves
its previous commit count, including swallowed errors, late producer failure,
invalidated chance callbacks and third-epoch attempts.

An independent Python Fraction allocator and scalar model check every emitted
R/A/policy coordinate, exact cached-read/stage/commit ledgers, all resource
columns and seven altered frames. Complete source capture and original
process/build/invocation receipts precede both modes' execution. Saved-only
replay and portable native/sanitizer CI remain separate acceptance checks.
