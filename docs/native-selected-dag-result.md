# Native selected DAG: frozen verification and complete-call result

The explicit native backend trains the same directly constructed four-street
selected game without a materialized public occurrence tree or dense hand map at
each decision. This is a bounded integration and cost result. It does not solve
full-deck Hold'em, compress distinct strategy histories or establish commercial
accuracy or a general memory reduction.

## Fixed paired cost and quality

Both backends use direct shared construction, packed zero-delay CFR+, the original
22-world weighted/shared-future game, rank capacity 64 and Python 3.12.14 on the
recorded Windows/MSVC build. The fixed sequence has three alternating untraced
T100 pairs, one separate traced T100 pair and one untraced T1000 pair. All five
pairs have identical complete policies, diagnostics, private-pair probabilities
and game/strategy censuses. There are ten training calls and five native calls.

| Complete-call observation | Python direct | Native direct |
| --- | ---: | ---: |
| T100 median, three samples each | 17.221862 s | 0.562783 s |
| T1000, one sample each | 103.703905 s | 0.916397 s |
| Traced T100 Python allocation peak | 2,288,891 bytes | 2,382,287 bytes |
| Traced T100 Python process lifetime peak | 29,589,504 bytes | 29,921,280 bytes |
| Native process lifetime peak for traced call | not applicable | 3,043,328 bytes |

These include preparation, support/context/row admission, wire/ranks, native
launch where selected, independent Python diagnostics and serialization.
Timing establishes a speed result on this fixture/build. T1000 is a single
observation per backend. Traced Python allocation increases about 4.1%; the three
memory measurements are separate and never summed. No overall memory saving is
established, and these values cannot be substituted for earlier studies' costs.

Both saved T100 policies miss the unchanged exact normalized-policy
`NashConv <= 0.001 BB` target (about `0.011805990010147357 BB`). Both T1000 policies
pass it with identical exact metrics (about `0.00039973881514413504 BB`). Rational
threshold comparisons, complete normalization ledgers and all misses remain in
the archive. A finite-iteration target pass is not an unrestricted equilibrium or
commercial-convergence claim.

The native receipt retains 99 public vertices/173 edges and 259 vertex/prefix
contexts/321 context edges for 1,462 logical visits. There remain 1,200 information
rows and 2,402 action slots. Input is 4,232 bytes; complete worlds, prefix/pair edges,
expanded native nodes and per-decision dense maps are absent. Prefix ordinals,
context summaries, complete Python history/output and numeric strategy buffers
remain charged; contexts can approach logical size. These entry counts do not
prove a general asymptotic or process-memory improvement.

## Held-out correctness and preserved gates

The separate 96-world T100 probe uses the same retained six-board/four-hand-range
case as the earlier [held-out study](native-selected-heldout.md), without running
archived source. Native direct output matches every preserved complete policy,
private-pair probability and diagnostic metric. A separate
[independent saved review](../benchmarks/results/native-selected-dag-v1/native-dag-heldout-independent-receipt.json)
authenticates all source/archive bytes and performs fresh physical numeric replay
of all 2,224 rows, with maximum metric gap `1.11e-16` and no training/native execution.
Its receipt SHA-256 is
`badc8254f364bccc19b8f6e2a0b3b9449eadc9c4e08baa0b392183c4e543d4ae`.

Exact certification rejects the complete 2,224-row policy at its unchanged
2,048-row shape cap. T1000 rejects the unchanged 500-million scan envelope before
ranking or native execution. Both rejections and zero-call evidence are retained;
this probe supplies no larger exact quality pass or paired timing claim.

## Acceptance and next dependencies

Strict MSVC C++20 compilation passes, as do 117 affected controls including the
old/new compiled backends and 36 focused controls under optimized Python.
Independent scrutiny adds a separate world-recursive CFR+ oracle: a shared
context reached through two histories produces different policies, all 12 native
slots agreeing within `1e-12`. Blocker-induced holes, unsupported selected boards,
GC-disabled plan release, malformed dimensions/partitions/order/postorder,
source drift and native failure without fallback are tested.

At the measured source, full unit CI passes on Python 3.11/3.12/3.13, along with
new/legacy compiled controls, ASan/UBSan, documentation and presentation checks.
The [captured code CI](../benchmarks/results/native-selected-dag-v1/native-dag-code-ci.json)
is separate from the final evidence-head checks and merge state in
[PR #256](https://github.com/ajpaulson18-design/openpoker-lab/pull/256).

Remaining foundational barriers include complete history/strategy/output growth,
private-pair scans, scalable independent certification, finite betting/money
contracts and full-deck reach/payoff integration. The prior
[numerical factorization boundary](../benchmarks/results/native-selected-heldout-v1/numerical-factorization-review.md)
remains: rounded legacy pair probabilities are not exactly rank-one, so a factored
payoff replacement cannot silently claim the same arithmetic game.
