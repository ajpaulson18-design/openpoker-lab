# Complete frozen-update study controller

Status: implemented, pre-execution controls pass, complete numerical batch unrun.
`scripts/run_virtual_frozen_update_study.py` runs only the full fixed PROOF9/v1
experiment: two native ADMIT scopes and all 2,520 boards for both proposal laws.
It has no board subset, automatic retry or partial-batch resume option.

Run from its clean committed source checkout, with the exact committed HEAD and
a new external output directory. On Windows inherit the selected MSVC build
environment. The controller requires enough free space for the full admitted
evidence allowance before entering any EVAL request. An output directory already
present is a preserved attempt and cannot be reused.

## Execution and saved evidence

The exclusive claim records the controller PID and claim time for later process
queries. Metadata alone never establishes liveness. A bounded append-only progress
log records phases and native requests. The actual outer process/tool handle and
child exit observations remain authoritative.

The controller captures the complete clean committed tree and its raw source
bytes externally, builds the explicit native probe, and authenticates the actual
compiled source set, all 198 extracted Boost headers, executable and compiler
bytes. The builder now records compiler SHA-256 before compilation and checks it
again afterward. A compiler-version string alone is insufficient.

One sampled-reference context and one q-free admission prepare the complete
rank-free resource plan. Cumulative controller meters reserve each named numeric
family, reference artifact bytes, request/output limits and combined per-call
metadata. Both frozen native worst-law ADMIT requests must pass with zero chance
callbacks and combined transport/native work below the original per-game cap.
Only then is the q-free expected update computed once and streamed to its exact
artifact before comparison. Readback supplies the saved expected snapshot.

For every board under each law, the controller preserves request, bounded native
stdout/stderr and actual exit, computes the independent sampled reference,
exports and reloads its exact rows, and passes both saved representations to the
exact per-board comparator and persistent expectation owner. Every numerical
failure ends that attempt. Each law must finalize against the complete q-free
expected rows before its owner is released. Attempt and completion counts are
separate, including failed native error frames.

A successful controller result is labelled fixed-profile update identity with
saved-only acceptance pending. It does not claim actual sampling, training,
policy quality or overall-goal completion. Independent saved replay and real
corruption witnesses remain required. Packaging/review failures must be repaired
from saved outputs; never rerun this frozen producer merely to repair a harness.

## Source guard composition and measured cost

The earlier full-tree capture/recheck authenticated 2,373 files/358,262,859 bytes
in 117.575 seconds. Repeating historical non-input archive reads for every board
would measure evidence I/O rather than improve mathematical validation.

The controller retains full-tree/raw checks at batch boundaries. Around every
native request it authenticates an explicitly saved execution closure: every
loaded Python module inside the project, all compiled source/build inputs,
`.gitattributes`, `pyproject.toml`, actual extracted headers, compiler and probe.
A new project import rejects rather than silently widening the closure. HEAD,
attributes, cleanliness and exact raw input hashes are checked; no line-ending
exception permits later drift. Full-tree terminal checks still bind all retained
project files. The original larger authentication-byte allowance remains
conservative. This changes evidence scheduling, never the game, board universe,
policy, comparison scope or native limits.
