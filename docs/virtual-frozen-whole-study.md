The composition audit found that q-free preparation builds the independent
numeric template within its census, performs a literal validation walk, and
builds another template for expected-value computation. Its old setup receipt
covered the last build rather than this complete chain.

Independent template and literal helpers now accept one optional shared numeric
Budget. Default component behavior is unchanged. Integration passes the same
owner through all preparation calls; no child gets a reset numeric meter. The
q-free chain reserves 200 million work, one million logical entries, two billion
created integer bits and 4,096-bit intermediates before preparation. Fixed N9
prefix/proposal work and scratch are reserved before those builds. Runtime
expected-value computation retains its separate existing allowance, and the
combined single-call 500-million work and other original caps still apply.
The sampled reference context also shares one numeric setup owner across its
template and literal walk. This changes accounting, not betting rules or priors.

## Complete resource families

The plan includes all 5,040 EVAL requests, two rank-free native ADMIT scopes,
one immutable sampled-reference context, one q-free oracle, every exact per-board
comparison, both law accumulators, and semantic artifact export and readback.
One law accumulator is retained at a time; the enclosing controller must release
it after finalization before constructing the other. Only its result receipt
persists. The peak-entry model conservatively includes both possible q-free row
representations plus native state, sampled rows, codec state, comparison scratch
and preparation scratch. Logical entries and integer payload are distinct from
Python/native heap and RSS.

Native logical work, reference/Fraction work, comparison work, accumulator work,
codec byte/field work and authentication byte reads are reported separately.
There is no fabricated cross-model CPU-work total. Each family has an explicit
reduce-only experiment cap. Both accumulator allowances are charged; no owner
meter is reset to evade admission.

File families include bounded native stdout, 64 KiB stderr per request, 1,025-byte
request frames, 64 KiB per-call metadata, the complete reference export family,
a one-GiB source snapshot, headers/build evidence, controller/failure logs and
saved corruption controls. The allowance keeps originals and one archive,
without presuming compression savings; archive headers receive their own bound.
The current complete artifact cap is 64 GiB. The controller must enforce every
file-family bound while writing, retain first errors, and check available storage
before execution. This is an upper allowance, not a claimed measured file size.

Source admission permits at most 4,096 paths, 1,024 bytes per path, 64 MiB per
source file and one GiB total source bytes. Authentication reserves a complete
closure read before/after every native request and outer guards, with bounded
streaming I/O. Compiler/header/executable identities are included separately.
The plan does not establish that actual source or filesystem state passes these
limits. A preliminary current checkout census observed 2,357 tracked files,
358,169,452 bytes and a largest file of 23,204,718 bytes; this dated path/stat
observation is not a source-authentication receipt.

The settled-source combined controls pass all 28 cases normally and optimized,
with stable source hashes. They cover whole-plan reduce-only limits, shared
numeric meter propagation, pre-build setup rejection and existing reference
mathematics. The [development manifest](../benchmarks/results/virtual-frozen-whole-study-development-v1/manifest.json)
pins complete control streams and a separately generated rank-free resource plan.
The positive full-study update and expectation gates remain unrun.
