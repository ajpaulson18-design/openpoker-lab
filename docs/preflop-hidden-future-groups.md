# Hidden-future grouping for the flop-checkdown game

`solve_preflop(..., postflop_scope="flop-checkdown", future_indexing="flop-sign", ...)` optionally groups the already enumerated physical futures for training and exact diagnostics. The existing positive-delay CFR+, public-batched training/diagnostics and public-vector admission requirements apply. The default `future_indexing="original"` retains the prior numerical path and payload. Grouping is rejected before enumeration in the all-streets game.

Within this explicit model, all decisions stop after flop betting. For each private pair and public flop, folds depend on total physical mass and showdowns on signed mass. Grouping by `(SB hand, BB hand, public flop, final sign)` retains both statistics mathematically. Final signs remain categorical -1, 0 or 1, including ties. The helper uses bounded per-group Neumaier summation in deterministic first-seen order and never renormalizes the selected joint distribution. Future cards do not become information available to either player. Changed summation order can produce small numerical differences; this is not bitwise policy equivalence or a formal floating-point error proof.

Original seven-field physical worlds still govern enumeration/candidate/world-iteration limits, tree construction, legal information sets, selected/reachable outcomes, private-pair probabilities and all public physical counts. The grouped five-field view is used only for training, convergence checks and final exact vector diagnostics, then released before output. Compact indexing first copies the original physical rows; its old copy/reference charges and policy restoration remain in force. The shared postflop/turn/river kernels and AI Coach are unchanged.

Admission deliberately retains the entire original-world vector envelope, including inactive future prefixes, then adds grouping construction against the same 500,000,000 modeled-loop cap. No old cap is relaxed. Before grouping or private-index copying, a separate O(1) bound reserves `128 + 22*N` logical reference slots under an 8,000,000-slot cap and `32 + 24*N` modeled grouping loop entries, with at most one group per original world. The reference bound charges original seven-field rows, map keys/accumulators, and grouped output/list overlap; Python headers, allocator overhead and RSS are excluded. Metadata uses `preflop-public-vector-future-group-budget-v5` and names the retained reference-budget version. These are conservative structural counts, not runtime or allocated-byte predictions.

The [predeclared experiment](../benchmarks/preflop-hidden-future-groups-v1.json) uses the same [two-flop, three-chip checkdown game](preflop-flop-checkdown.md): 4,704 selected future candidates, 11,880 compatible physical worlds, 76 public states, 32 decisions and 57 information sets. Grouping produces **16 training rows**. Three alternating complete90/delay45 pairs include enumeration/ranking, trees, original-world admission census, optional grouping, training, exact diagnostics and JSON serialization. Inputs are preallocated; pre-call garbage collection and independent replay are outside timing. Only serialized text from the previous timing arm remains live, with alternating order; no previous parsed policy or grouping structures are retained.

Observed medians are **0.819967 versus 0.693890 seconds**, **15.38% lower**, clearing the predeclared 5% gate. These are one-host fixture observations, not statistical or universal speed guarantees. Existing vector admission is intentionally higher: **938,987 versus 1,224,139** modeled loop entries for the requested 90 sweeps, including 285,152 extra grouping entries; faster measured execution does not justify loosening admission.

Separate complete10/delay5 calls plus JSON peak at **10,131,239 versus 6,704,480 traced Python bytes**, **33.82% lower**. The prior memory policy and serialized text are retained on disk after tracing and released before the next trace. Disk retention, digests and replay are excluded from tracing, as are native allocations and process RSS. This is not a higher-iteration or whole-process memory guarantee.

Both arms of all three timed pairs independently replay every original physical outcome using numeric poker rules and exact legal visible-information best responses. The independent 90/delay45 NashConv is **0.00123906973908949** for original rows and **0.00123906973914389** for grouped rows; both meet the unchanged **0.005-chip** target. Maximum timed-policy probability difference is **2.657e-12**, below the predeclared 1e-9 tolerance. Physical outputs, strategy identities/order and action structure match exactly. Maximum difference between arms in independently replayed scalar metrics is **7.067e-14** across timing and memory runs; maximum production-versus-oracle scalar discrepancy is **2.332e-14**. The 10/delay5 policies retain NashConv **0.175182033386** and **miss the target** in both arms.

The [harness](../scripts/benchmark_preflop_hidden_future_groups.py) checks hashes and revision again before saving. The two arms have intentionally different resource metadata and slightly different policies; full serialized payload equality is not required or claimed.

Focused validation passed **23 tests**, including ten new helper/integration tests for weighted/blocker/tie statistics, mass/sign preservation, first-seen order, default parity, independent full-world replay, compact/checkpoint composition, cap ordering, and view cleanup after success/failure. Full applicable checks must pass before merge. Luna independently implemented/tested the bounded helper and reviewed integration and experimental methodology; lead integrated the opt-in, added admission/replay/cleanup tests and froze/measured complete calls. The implementation derives from this repository's own physical game model; no third-party source, dependencies or proprietary solver output were incorporated.

All results remain limited to this finite conditioned preflop/flop game with forced future checkdown and narrow private ranges. They do not certify unrestricted NLHE, full-deck/broad-range preflop, multiway, or all-streets equilibrium accuracy. This opt-in does not resolve the earlier per-flop template rejection for the all-streets raised game.
