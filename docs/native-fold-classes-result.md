The original T60 V5 receipt records four masks/four member entries, 168 setup
entries, 18,900 SB class calls, 3,060 BB class calls and 15,840 BB literal calls.
Its successful callbacks execute 14,341 class buckets and 28,682 own-hand checks.

and entered/completed counters, not allocator bytes or CPU measurements.

All old query allowances remain. Original T60 native combined work changes
from 421,423,933 to 421,571,773; separate whole-request host-plus-native work
changes from 443,028,403 to 444,849,155. Both remain under the unchanged 500m
ceiling. The native retained envelope is 539,716 entries for V5, below 2m.
Native setup and host proof are additional work; neither is query credit.
Existing literal-map primitive-cost accounting remains preexisting and is not
newly proved by this study.

Both profiles reject 16×16 T10 with the history-index bounded input-scan message,
original T100 with the external shared reservation message, and original T1000
with complete callback-work admission. No admitted-frontier gain is observed.
The 16×16 failure is a different gate from fold application, so fold credit alone
is not shown to unlock it. Rejected native internals remain unknown in raw receipts.

The next major candidate is an independent saved-policy value/best-response
verifier that avoids complete-world construction. Reuse existing saved larger
policies and preserve their earlier unknown receipts. It must sum hidden outcomes
before own-hand maximization, carry opponent reach by full visible history, keep
the global joint normalizer, independently model legal rules/ranks, and bound
exact fraction growth. This is a proposed gate, not an implemented certificate.
Full-deck chance/reach/training, broader public-game/strategy storage, unrestricted
convergence and commercial accuracy remain unresolved.
